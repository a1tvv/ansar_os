# Ansar OS

Внутренняя система для работы сети магазинов Ansar. Начинается с отчётов о продажах, которые никогда не удаляются автоматически.

## Возможности

- **Отчёты:** продажи за любой период начиная с 2019 года — KPI, разбивка по филиалам и топ товаров. Всё считается из базы данных
- **Вечный архив:** отчёты никогда не удаляются автоматически; удаление вручную требует подтверждения и записывается в журнал аудита
- **Приёмка товара:** документы приёмки с позициями, массовый ввод, статус оплаты, проведение и листы со штрихкодами для печати
- Готова оболочка интерфейса для следующих модулей: склад, перемещения, закупки, сотрудники и другие
- Django-админка для всех данных и генераторы демо-данных

## Стек

Python · Django · PostgreSQL (для разработки — SQLite) · WhiteNoise

## Быстрый старт

```bash
git clone https://github.com/a1tvv/ansar_os.git && cd ansar_os
python3 -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt
python manage.py migrate && python manage.py seed_demo
python manage.py runserver
```

Если `PG_DB` не задана, проект запускается на SQLite. Открой http://127.0.0.1:8000 — откроется модуль отчётов. Для админки выполни `python manage.py createsuperuser` и открой `/admin/`.

## Настройки

Задай их как переменные окружения (см. [`.env.example`](.env.example)):

| Переменная | Для чего |
|---|---|
| `DJANGO_SECRET_KEY` | Секретный ключ Django. Без него используется небезопасный ключ для разработки, поэтому в продакшене задавай его всегда |
| `DJANGO_DEBUG` | По умолчанию `1` (включено); в продакшене поставь `0` |
| `DJANGO_ALLOWED_HOSTS` | Имена хостов через запятую; по умолчанию `*`, поэтому в продакшене задай их |
| `PG_DB`, `PG_USER`, `PG_PASSWORD`, `PG_HOST`, `PG_PORT` | Подключение к PostgreSQL |
| `DATABASE_URL` | Другой вариант: одна строка подключения, например на serverless-хостинге |
